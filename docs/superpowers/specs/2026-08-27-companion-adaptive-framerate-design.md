# 儿童多模态陪伴 — 画面变化自适应帧率设计文档

- 日期：2026-08-27
- 状态：已评审通过，待实现
- 前置：`2026-08-27-companion-video-frame-tuning-design.md`（视频帧 320 宽 + onDemand 5s，已实现）
- 相关分支：dev

## 1. 背景与目标

视频帧抓取是固定频率：`continuous` 1s 一帧、`onDemand` 5s 一帧。读绘本时孩子翻页，固定 1s 频率可能跟不上（模型在旧页继续讲、或提示翻页时已翻过去）。本设计引入**画面变化自适应帧率**：画面突变（翻页）时临时提速，走动或静止时恢复正常/回落，从而在跟手与计费之间取得平衡。

## 2. 范围

### 2.1 范围内

- `VideoFrameSource.ts`：从固定 `setInterval` 改为 `setTimeout` 链的动态间隔
- 每次抓帧额外生成 16×16 PNG 用于画面变化检测（不发模型）
- 状态机：突变→加速、持续变化→恢复正常、静止→平滑回落
- `continuous` 与 `onDemand` 两个模式都启用

### 2.2 范围外

- 光流检测（区分「连贯运动」vs「剧变」——突变检测的已知局限，留作后手）
- 危险场景检测（目标检测/深度估计，另见 README P0）
- 换库拿真视频帧

## 3. 状态机

```
每帧抓完后，比较 16×16 PNG 与上一帧的差异：

  if 差异 ≥ 30%（变化）:
      if 上一帧是「静止」→ 突变（翻页）→ 加速：间隔 = 基础间隔 ÷ 3
      else → 持续变化（走动）→ 恢复正常：间隔 = 基础间隔

  else（静止）:
      间隔 = min(间隔 × 1.5, 基础间隔)   // 平滑回落
```

### 3.1 关键设计点

1. **突变 vs 持续靠「上一帧是否也在变化」区分**——翻页是「静止→突变」，走动是「持续→持续」。走动时即使第一帧误判为突变加速，下一帧检测到持续变化立即恢复正常，最多多抓一两帧，不持续烧钱。
2. **检测图用 16×16 无损 PNG**——PNG 无损，base64 差异 ≈ 像素差异；缩到 16×16 后噪声消失，比较可靠。仅用于检测，不计费。
3. **动态间隔用 `setTimeout` 链**——`setInterval` 固定间隔无法逐帧调整，改为每次抓帧后按新间隔安排下一次。

## 4. 参数

| 参数 | 值 |
|---|---|
| 基础间隔 | `continuous` 1000ms / `onDemand` 5000ms（沿用现有常量） |
| 加速倍数 | 3x（间隔 ÷3） |
| 最小间隔下限 | 200ms（防无限加速） |
| 差异阈值 | 30% |
| 回落步长 | 每帧间隔 ×1.5，封顶基础间隔 |
| 检测图尺寸 | 16×16 PNG |

## 6. 边界情况

- **冷启动**：第一帧无「上一帧」可比，按基础间隔，不加速
- **走动**：持续变化 → 恢复正常间隔，不加速
- **边走边翻书**（叠加）：突变+持续交替，可能间歇加速——突变检测的已知局限，光流才能完全区分
- **光线突变**（开灯/关灯）：整幅亮度剧变，误判为「变化」触发一次加速——无害（多抓一帧），下一帧回落
- **差异计算**：base64 字符串差异占比，需排除「检测图尺寸变化」导致的长度差异（固定 16×16 尺寸应恒定）

## 7. 测试

- 纯函数文档化断言：状态机转换、差异判定
- 真机验收：翻页时帧率提升、走动时帧率正常、静止时平滑回落
