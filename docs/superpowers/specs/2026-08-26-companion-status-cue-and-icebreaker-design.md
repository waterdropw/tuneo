# 儿童多模态陪伴 — 状态提示音与破冰设计文档

- 日期：2026-08-26
- 状态：已评审通过，待实现
- 前置：`2026-08-25-children-multimodal-companion-design.md`（语音版，已实现）、`2026-08-26-children-multimodal-companion-video-design.md`（视频版，已实现）
- 相关分支：dev

## 1. 背景与目标

当前陪伴会话的状态切换（连接中 / 聆听中 / 回复中 / 出错）仅靠文字小字显示，孩子无法感知「AI 是否活着、是否在听」。同时 `prompts.json` 默认「保持安静等孩子先开口」，对 2–6 岁幼儿不成立——孩子不主动，AI 就一直沉默，体验上像「坏了」。

本设计做两件小改动，不改架构：

1. **状态提示音/震动**：连接成功、出错/断线时用系统震动反馈，让状态「可感知」。
2. **破冰 + 连接问候**：改 `prompts.json`，让 AI 在开场主动问候、长时间沉默时主动引导。

> 最终产品形态是无屏挂脖小盒子，震动反馈与主动发声都是该形态下的关键体验；本次在手机端先验证。

## 2. 范围

### 2.1 范围内

- 连接成功、出错/断线两种状态的系统震动反馈（RN 内置 `Vibration`，无新依赖、无资源文件）
- `prompts.json` 三个年龄段各加「开场问候」与「沉默破冰」两条指令

### 2.2 范围外

- 无屏模式 / UI 隐藏（留到量产前）
- 本地音频提示音文件（本设计用系统震动）
- 客户端主动触发模型发声（`response.create` 等）——若 prompt 验证不生效，再迭代加
- 家长端

## 3. 架构与组件

### 3.1 修改 `src/navigation/screens/Companion.tsx`

在 `handleEvent` 里加两处震动，顶部新增 `import { Vibration } from "react-native"`。

| 状态 | 触发点 | 震动 |
|---|---|---|
| 连接成功 | `case "session-updated"` | `Vibration.vibrate(80)` 轻震一下 |
| 出错/断线 | `case "error"` | `Vibration.vibrate([0, 200, 100, 200])` 连续两下 |

说明：断线已由 `OmniRealtimeService` 的 `onclose`（`event.code !== 1000`）统一转成 `error` 事件，故 `error` 分支天然覆盖「出错」和「断线」两种。

### 3.2 修改 `src/config/prompts.json`

保留原有「读绘本 / 危险警示 / 保持安静」的场景判断，只在**开场**和**长时间沉默**两处改为主动。三个年龄段各自加同样结构的两条指令，用各自年龄段的语气表述。

以 `toddler` 为例，把结尾那句

> 其他时候保持安静，耐心等小朋友先说话或提问，不要一直说个不停。

改为：

> - **开场**：对话刚建立时，主动用一句简单温暖的问候打招呼（如「你好呀，我们一起玩吧」）。
> - **沉默破冰**：如果小朋友好一会儿没说话，可以温柔地主动问一句（如「你在玩什么呀？」），但不要频繁打扰，破冰后继续安静等待。
> - 其他时候保持安静，耐心等小朋友先说话或提问，不要一直说个不停。

`child` 用更丰富的语言、`auto` 用语言难度匹配孩子的措辞写同样的开场/沉默破冰指令。

## 4. 数据流

无新增数据流。震动在既有 `handleEvent` 事件分发路径上触发；破冰/问候走既有 `session.update` 的 `instructions` 字段下发给模型。

```
[连接成功] session.updated → handleEvent("session-updated") → Vibration.vibrate(80)
[出错/断线] error / onclose(code≠1000) → handleEvent("error") → Vibration.vibrate([0,200,100,200])
[开场/沉默] 由 instructions(prompts.json) 驱动模型主动发声（待验证，见 §5）
```

## 5. 已知风险与验证判据

当前为服务端 `semantic_vad` 模式，模型**默认只在检测到孩子说话后才回应**。纯靠 prompt 让它在「开场」「沉默」时主动发声**可能不生效**——模型未必会在无输入时主动产生 response。

| 验证结果 | 含义 | 下一步 |
|---|---|---|
| 连接后模型主动问候 | prompt 生效 | 无 |
| 连接后模型沉默 | VAD 模式不主动发声 | 迭代加客户端主动触发（连接后发 `response.create` 或空音频触发） |

## 6. 测试

- 真机验证：连接成功轻震一下、断线/出错连震两下。
- 真机验证：连接后模型是否主动问候；沉默一段时间后是否主动破冰。
- prompt 文案为纯文本改动，无单测；震动逻辑无独立可单测的纯函数（直接调 `Vibration` API）。

## 7. 明确不做的（YAGNI）

- 无屏模式 / 隐藏聊天与调试 UI
- 音频提示音资源文件
- 客户端 `response.create` 主动触发（除非 prompt 验证失败）
- 更多状态（聆听中 / 回复中）的震动反馈
